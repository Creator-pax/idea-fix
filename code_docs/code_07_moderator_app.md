# Часть 7. moderator_app.py — десктоп-панель модератора

Файл (~2298 строк) — desktop-приложение на **customtkinter** (обёртка над tkinter).
Читает ту же `bot_data.db`, что и бот, и позволяет модератору: смотреть/подтверждать
заявки на регистрацию, управлять пользователями (роли, блокировка, лимиты, удаление),
смотреть логи ИИ и ошибок, заметки, обрабатывать заявки на вступление в школу, делать
массовую рассылку, экспортировать данные в CSV.

**Запуск: `python moderator_app.py`** (из корня проекта).

## Архитектура (строки 1–102)

- Стандартные импорты: `asyncio`, `csv`, `os`, `shutil`, `sys`, `time`,
  `from tkinter import filedialog, messagebox, ttk`.
- `import customtkinter as ctk` — «skин» поверх tkinter: `CTk`, `CTkTabview`, `CTkFrame`,
  `CTkButton` и т.п.
- `import database as db` — все запросы к БД (GUI НЕ обращается к SQLite напрямую).
- `from bot_instance import bot` — бот-инстанс для уведомлений: `bot.send_message` в
  асинхронном стиле через `asyncio.run()` (по одному сообщению на действие).

Ключевая идея разделения: панель не знает схемы БД (всё через `db.*`) и не работает с
Telegram напрямую (только через `bot`). Так же устроены и обработчики бота.

## Хелперы (строки 104–215)

- `ROLE_LABELS` — список пар `(значение в БД, подпись со смайлом)` для ролей:
  `pending` («⏳ Ожидает»), `student`, `teacher`, `moderator`, `rejected`.
  Один список — подписи в UI и значения в БД не расходятся.
- `role_display(role)` — переводит техническую роль в человекочитаемую подпись.
- `ts_to_str(ts)` — Unix-секунды → строка даты (пустая, если нет).
- `ai_mode_display(mode)` и похожие — читаемые названия режимов ИИ.
- Прочие мелкие хелперы форматирования — единый источник подписей.

## Класс `DataTable(ctk.CTkFrame)` (строка 215)

Таблица на базе `ttk.Treeview` внутри CTk-фрейма:

- `__init__(parent, columns, headers, hidden_col, **kw)` — создаёт `Treeview` с колонками.
  `columns` — список имён колонок (счёт как в Treeview: первая колонка — `('#0')`),
  `headers` — их заголовки, `hidden_col` — имя колонки, в которой будет храниться
  служебное значение (например user_id или id заявки), скрытое от глаз.
- Настраивается тёмная/светлая тема под `ctk` (`ttk.Style`, `configure` для `Treeview`).
- Методы:
  - `set_rows(rows)` — замена содержимого: `delete` всех строк и `insert` с `values`.
    Для каждой строки `values` должны соответствовать списку колонок (длина совпадёт),
    иначе Tk упадёт с `TclError`.
  - `selected_value()` — возвращает значение `hidden_col` выбранной строки (или None).
    Читается из `self.tree.item(self.tree.selection(), "values")[hidden_idx]`.
  - `clear()` — очистка таблицы.
  - `set_command(...)` / двойной клик — привязка действия на выбор строки.

Панель использует именно этот класс во всех вкладках, а во `view_user_details` и т.п.
служебная колонка хранит `user_id`/`request_id`, по которому потом выполняются действия.

## Окна-диалоги

### `DetailWindow(ctk.CTkToplevel)` (строка 408)

Модальное окно просмотра деталей: название + текст (большой `CTkTextbox` или `CTkLabel`).
Открывается для просмотра вопроса/лога ИИ (раскрывает текст скрытой колонки) и для
просмотра профиля пользователя. Кнопка «Закрыть».

### `SendMessageWindow(ctk.CTkToplevel)` (строка 444)

Окно личного сообщения пользователю от имени бота:
- Поле ввода текста + кнопка «Отправить».
- `send()` (строка 488) — собирает текст; если пустой — подсказка; иначе запускает
  асинхронную отправку.
- `_send_async()` (строка 516) — `asyncio.run(bot.send_message(chat_id=..., text=...))`
  в GUI-потоке. При ошибке — messagebox с причиной. (Отправка уходит в отдельный event loop,
  поэтому GUI не «зависает» сетью.)

### `EditUserWindow(ctk.CTkToplevel)` (строка 524)

Окно редактирования пользователя:
- `FIELDS` — 7 полей (имя/ФИ, класс, школа, телефон, роль и т.п.).
- При открытии заполняется значениями из `db.get_user(user_id)`.
- `save()` (строка 586) — по каждому полю вызывает `db.set_user_field(...)`; при ошибке —
  messagebox. После сохранения закрывает окно и просит обновить данные.

## Класс `ModeratorApp(ctk.CTk)` (строка 608)

### Конструктор (`__init__`, ~строки 617–735)

- Заголовок окна, размер, тема (`ctk.set_appearance_mode`).
- Создаёт `CTkTabview` с вкладками:
  `📊 Обзор`, `📋 Заявки`, `👥 Пользователи`, `🤖 Логи ИИ`, `⚠️ Ошибки ИИ`,
  `📝 Заметки`, `🏫 Вступление`, `📢 Рассылка`, `💾 Экспорт`.
- В каждой вкладке — свой `DataTable` + кнопки действий.
- Кнопки «Обновить» вызывают `refresh_all()`; вешается таймер автообновления
  (`after(...)` → `_auto_refresh_tick` перечитывает данные и не роняет GUI, если БД
  временно недоступна — обёртки try/except).
- В конце `__init__` — `self.after(...)` стартовое автообновление.

### Вкладки и загрузка данных

- **`load_stats()`** (~L1302+) — «📊 Обзор»: счётчики (всего пользователей, заявок pending,
  запросов ИИ, ошибок, заметок, заявок на вступление) — через `db.get_all_users`,
  `get_pending_users`, `count_ai_requests_total`, `get_total_notes_count`,
  `get_all_join_requests` и т.п. Каждый счётчик обёрнут отдельно в try/except.
- **`load_pending()`** — «📋 Заявки»: `db.get_pending_users()` → список user_id; по каждому
  `db.get_user(uid)` → строка таблицы «имя, роли, дата, статус» + скрытая колонка с user_id.
- **`load_users()`** — «👥 Пользователи»: `db.get_all_users()` → строки с анкетой, ролью,
  блокировкой, лимитами; скрытая колонка — user_id.
- **`load_ai_logs()`** — «🤖 Логи ИИ»: `db.get_ai_logs(limit=...)`; строка — user, вопрос
  (обрезанный), дата. Полный текст вопроса — в скрытой колонке; просмотр — `view_question`.
- **`load_errors()`** — «⚠️ Ошибки ИИ»: `db.get_ai_errors(limit=...)`; кнопка
  «Очистить» → `db.clear_ai_errors()`.
- **`load_join_requests()`** — «🏫 Вступление»: `db.get_all_join_requests(...)`;
  кнопки «Принять»/«Отклонить» → `db.approve_join_request(id, self.admin_id)` /
  `db.reject_join_request(...)`.
- **`load_notes_for_user(user_id)`** — «📝 Заметки»: `db.get_notes(uid)` в текстовое поле.
- **`refresh_all()`** — вызывает все `load_*` подряд, каждая — в своём try/except, чтобы
  одна неудача не сломала остальные вкладки.

### Выбор целевого пользователя

- `_selected_pending_id()` (строка 1570) — user_id выбранной строки вкладки «Заявки»
  через `selected_value()`.
- `_target_user_id()` (строка 1580) — user_id выбранной строки вкладки «Пользователи».
- `_require_target(what)` (строка 1665) — предупреждение «выбери пользователя/заявку»,
  если ничего не выбрано.

### Действия по кнопкам

- `approve_selected()` (1624) / `reject_selected()` (1642) — подтвердить/отклонить заявку:
  `db.approve_user(uid)` (`approved=1`, роль из role_requested) / `db.set_role(uid, "rejected")`,
  затем уведомление пользователя через `bot` (в try/except — «не смог уведомить» не ломает),
  `refresh_all()`.
- `set_role_for_selected()` (1681) — смена роли через выпадающий список; новый `db.set_role`.
- `toggle_block()` (1706) — `db.toggle_blocked(uid)` + обновление строки.
- `set_limit_for_selected()` (1730) — ввод нового дневного лимита
  (диалог или поле); `db.set_user_field(uid, "ai_daily_limit", n)`.
- `reset_ai_usage()` (1750) — `db.reset_ai_usage(uid)`.
- `restore_rejected()` (1763) — вернуть отклонённого ученика в заявки (`role=pending`).
- `delete_user()` (1789) — подтверждение `askyesno` → `db.delete_user(uid)` + refresh.
- `view_user_details()` (1821) — открывает `DetailWindow` с карточкой пользователя.
- `edit_user_window()` (1868) — открывает `EditUserWindow`.
- `show_user_notes()` (1879) — заметки пользователя в отдельном окне.
- `view_question()` — раскрывает полный текст вопроса из скрытой колонки логов ИИ.
- `clear_errors()` — `db.clear_ai_errors()`.
- `_join_decision(accept)` → `_join_decision_row` — принятие/отклонение заявки на вступление.

### Рассылка (около строк 2140)

- `do_broadcast()` — собирает текст; `_broadcast_all_saved()` — для каждого одобренного чата
  `db.get_approved_chat_ids()` вызывает `asyncio.run(_broadcast_one(...))` (again, each в своём
  event-цикле, try/except на каждый чат), в конце — отчёт «разослано N из M».
- `_broadcast_one(chat_id, text)` — `await bot.send_message(chat_id=..., text=...)`.

### Экспорт (вкладка «💾 Экспорт»)

- `export_users_csv()` — `filedialog.asksaveasfilename` → CSV с пользователями
  (`csv.writer`, заголовки + строки из `db.get_all_users`).
- Возможны экспорты логов ИИ/ошибок аналогичным образом.

### Автообновление

- `_schedule_auto_refresh()` / `_auto_refresh_tick()` — периодический `after` (например раз
  в 30–60 сек) вызывает `refresh_all`; каждое обновление обёрнуто, чтобы GUI не падал при
  ошибках БД. Это и есть «груз данных при нажатии на вкладку» — при переключении вкладки
  данные перечитываются, поэтому панель всегда показывает свежую БД.

## `main()` (строка 2291)

```python
def main():
    app = ModeratorApp()
    app.mainloop()

if __name__ == "__main__":
    main()
```

- Создаёт единственный объект `ModeratorApp` и запускает цикл событий Tk (`mainloop`).
- `if __name__ == "__main__"` — запуск только при прямом выполнении файла.

## Примечание по ошибкам «при загрузке данных / нажатии кнопок»

Диагностика (проверена на текущей версии): старт окна, загрузка всех вкладок,
переключение вкладок и основные действия проходят без ошибок. Если ошибки всё же
появляются — вероятные источники:
- запуск не из venv (не установлены зависимости customtkinter/maxo);
- повреждённая БД (бот и панель в WAL-режиме) — стоит сделать бэкап `bot_data.db`;
- `db.*` вызов панели, отсутствующий в схеме (поле `role_requested` и пр.) — миграция
  `_migrate_users_columns` добавляет колонки при старте.

Проверить, какой Python запускает панель, и запускать её так:
`.\\.venv\\Scripts\\python.exe moderator_app.py`
