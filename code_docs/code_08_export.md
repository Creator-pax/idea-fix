# Часть 8. handlers/export.py — сохранение ответов ИИ в файлы

Файл (~980 строк) — конвертер ответов ИИ в 4 формата:
PDF, Word (.docx), RTF и PowerPoint (.pptx), с мастером настройки
**полностью на кнопках**. Добавляет к ответу ИИ кнопку «📄 Сохранить в файл».

## Что умеет модуль

1. **PDF** — генерирует ReportLab (Platypus: `SimpleDocTemplate`, `Paragraph`);
   фон каждой страницы — градиентная картинка, нарисованная **Pillow**.
2. **Word (.docx)** — собирает python-docx (шрифт, цвет текста, заливка
   параграфов фоновым цветом, кнопки-подпись авторов).
3. **RTF** — собственный генератор: минимум зависимостей, полный контроль
   над RTF-управляющими словами (`\rtf1`, `\colortbl`, `\chcbpat` и т.п.).
4. **PowerPoint (.pptx)** — python-pptx; презентацию можно разбить на
   **1/2/3/4/Авто слайдов**, каждый слайд получает свой Pillow-фон и шрифт.

Во все документы добавляется подпись `«Команда КУБ-СКРИПТ»` (константа
`AUTHORS_SIGNATURE`).

## Почему не Aspose.Words

Пользователь просил Aspose.Words для RTF и Word. Пакет `aspose-words`
**требует Python < 3.14**, а проект собран на Python 3.14.6, поэтому:
- Word → `python-docx`;
- RTF → ручной генератор.
Оба подхода дают тот же результат и не требуют лицензии.

## Ключевые идеи

- **Все настройки — кнопками.** Payload'ы `export_*` обрабатываются одним
  обработчиком `handle_export` с большой цепочкой `if payload.startswith(...)`.
- **Значения настроек — в данных FSM** (`fsm_context.update_data`), а не в БД:
  они нужны только на время мастера и стираются после сборки.
- **Конечный текст берётся из лога ИИ** (`db.get_ai_logs_for_user(uid, limit=1)`)
  вместо FSM — расшифровка: пользователь нажимает кнопку уже после ответа,
  когда состояние FSM раздела ИИ сброшено.
- **Дополнение к тексту генерирует ИИ** — `_prepare_extra` вызывает
  `_ask_ai` из `handlers/ai.py` (без цикла импортов).
- **Блокирующая работа — в потоках** (`asyncio.to_thread`): сборка файла и
  запрос к LM Studio не «замораживают» event loop бота.
- **Временные файлы** — в системной `tempfile`-папке; после отправки удаляются.

## Словари настроек (все — единый формат `{ключ: (подпись, ...)}`)

- `_FORMATS` — формат → (подпись кнопки, расширение): pdf/word/rtf/pptx.
- `_FONTS` — **30 шрифтов** → (имя для библиотек, ttf-файл в `C:\Windows\Fonts`).
  Все подобраны с поддержкой кириллицы (программа на русском): Arial, Times
  New Roman, Courier New, Georgia, Verdana, Tahoma, Comic Sans MS, Segoe UI,
  Gabriola, Владимир Сcript и др.
- `_BACKGROUNDS` — фон → (подпись, (верх, низ) градиента в RGB).
  Варианты: белый, кремовый, голубой, тёмный.
- `_EXTRAS` — что добавить в текст → (подпись, использовать ли ИИ):
  `none` / `title` / `summary` / `keywords`.

## Помощники мастера

- `_cancel_button()` — кнопка «❌ Отмена» (payload `export_cancel`).
- `_build_options_keyboard(options, extra_payload) -> KeyboardBuilder` —
  строит клавиатуру из словаря настроек: каждая кнопка получает payload
  `«<extra_payload><ключ>»`, в конце — кнопка «Отмена». Общий интерфейс
  для шагов «фон/дополнение/слайды» (второй элемент кортежа значения
  игнорируется).
- `_font_page_count()` — число страниц списка шрифтов (30 шрифтов ÷ 6 ≈ 5).
- `_build_font_keyboard(page=0) -> KeyboardBuilder` — клавиатура **одной**
  страницы шрифтов: 6 вариантов своими рядами, строка навигации счётчик
  страниц + «⬅️/➡️» (payload `export_font_page_<n>`), далее «Назад» к формату
  и «Отмена». 30 шрифтов в одной клавиатуре не помещаются — MAX отклоняет
  её с ошибкой **`errors.maxRows`**, поэтому шрифты разбиты на страницы.
- `_step_text(step_number, total=4, question) — шапка сообщения-вопроса.
  Для PowerPoint шагов 5, для остальных — 4.

## Обработчик `handle_export` (rower `callback`)

Декоратор `@router.message_callback(CallbackPayload("export_start", "export_cancel",
prefixes=("export_fmt_", "export_font_", "export_bg_", "export_extra_",
"export_slides_")))`.

Единый барьер доступа: пользователь существует, одобрен, не заблокирован
(`db.user_exists / is_approved / is_blocked`) — иначе молча выходим.

Ветки по payload:

1. **`export_cancel`** — показать «❌ Сохранение отменено» с кнопками в меню.
2. **`export_start`** — взять последний ответ из лога ИИ,
   положить `export_text`/`export_question` в FSM; спросить формат.
   Если лога нет — подсказка «Сначала задай вопрос ИИ».
3. **`export_fmt_<fmt>`** — сохранить `export_fmt`; показать первую страницу
   шрифтов.
4. **`export_font_page_<n>`** — листание списка шрифтов: показать страницу
   `<n>` (счётчиком и стрелками «⬅️/➡️»). Ветка проверяется ДО выбора шрифта,
   т.к. её payload тоже начинается с `export_font_`.
5. **`export_font_<font>`** — сохранить `export_font`; спросить фон.
6. **`export_bg_<bg>`** — сохранить `export_bg`; спросить дополнение.
7. **`export_extra_<extra>`** — сохранить `export_extra`.
   - Если `fmt == "pptx"` — дополнительный шаг: число слайдов
     (`export_slides_1/2/3/4/auto`).
   - Иначе — сразу `_generate_and_send(...)`.
8. **`export_slides_<n>`** — сохранить `export_slides` (±None для «Авто»),
   вызвать `_generate_and_send(...)`.

Защита от «грязных» payload: каждое значение проверяется на принадлежность
словарю (`fmt not in _FORMATS` и т.п.) — посторонние ключи молча игнорируются.

## `_generate_and_send(...)` — сборка и отправка

1. Из FSM достаёт текст и вопрос.
2. `callback_answer("Готовлю")` + `edit_message("⚙️ Собираю документ...")`
   — чтобы пользователь видел прогресс.
3. `asyncio.to_thread(_prepare_extra, extra, question, text)` — ИИ-дополнение.
4. `asyncio.to_thread(_build_file, fmt, text, title, extra_block, font, bg, slide_count)`
   — собственно сборка файла.
5. Читает байты файла, отправляет `send_media(BufferedInputFile.file(...))`,
   удаляет временный файл.
6. Ошибки ловятся: пользователю — понятное сообщение, в консоль — `Export error`.
7. Чистит все ключи мастера в FSM (`export_* = None`) — следующий экспорт
   начинается с чистого листа.

## `_prepare_extra(extra, question, text) -> (title, extra_block)`

- `none` — ничего: заголовок = вопрос, дополнение пустое.
- `title` — ИИ придумывает меткий заголовок (запрос к `_ask_ai`).
- `summary` — ИИ пишет вывод (3–5 предложений).
- `keywords` — ИИ выделяет 5–7 ключевых слов.
- Текст для ИИ обрезается (`excerpt = text[:3000]`), системный промпт
  требует вернуть **только** блок — без «вывод:» и пояснений.
- Заголовок по умолчанию — вопрос пользователя.

## Сборка файлов

### Общее

- `_font_helper(font_key)` — (имя шрифта, путь к ttf или None).
- `_palette(bg_key)` — (hex-цвет фона, цвет текста, цвет заголовка).
  Для тёмного фона — светлый текст.
- `_make_bg_image(bg_key, width, height)` — **Pillow**: вертикальный градиент
  от верхнего к нижнему цвету из `_BACKGROUNDS`, сохраняет PNG во временный файл.

### `_build_file(fmt, text, title, extra_block, font_key, bg_key, slide_count=None)`

Выбирает «сборщик» по `fmt`, к имени файла добавляет таймстамп:
`Ответ_ИИ_<unix>.pdf/.docx/.rtf/.pptx`. Возвращает `(путь, имя файла)`.

### PDF (ReportLab)

- Регистрирует выбранный TTF (`pdfmetrics.registerFont`), fallback — Helvetica.
- Гидра Bug при отсутствии ttf — не падаем.
- Pillow-градиент кладётся на **каждую** страницу (`onFirstPage`/`onLaterPages`
  → `canvas.drawImage`).
- Текст — `Paragraph`-ми по смысловым абзацам (`text.split("\n\n")`),
  спецсимволы экранирует `_esc_pdf` (это XML для внутренней разметки ReportLab).
- В конце — подпись `Команда «КУБ-СКРИПТ»` по центру.

### Word (.docx) (python-docx)

- `doc.styles["Normal"]` — шрифт по умолчанию (задаётся и `w:eastAsia`,
  чтобы кириллица тоже подтягивала выбранный шрифт).
- Параграфы добавляются одним помощником `_add_para`:
  размер/жирность/цвет/выравнивание + **заливка фона** (`w:shd` с выбранным hex).
- Дополнение от ИИ — курсивом, подпись авторов — жирная по центру.

### RTF (ручной генератор)

- `_rtf_escape` — экранирует `\ { }` и кириллицу в юникод `\uN?`.
- Шапка: `{\rtf1\ansi\deff0`, `\fonttbl`, `\colortbl` (текст/фон/акцент),
  дальше заголовок `\b...\b0`, тело (фон — `\chcbpat2`),
  дополнение, подпись `\pard\qc`.
- Цвета — через `_rtf_rgb` / `_rtf_rgb_hex`.

### PowerPoint (.pptx) (python-pptx)

- Слайд 13.33×7.5 дюйма (16:9), пустой макет + картинка-фон Pillow на **каждой**.
- Число слайдов: указанное (1/2/3/4) или **Авто** (≈2 абзаца на слайд,
  максимум 10). Текст делится на равные блоки; пустые слайды добиваются.
- Слайд 1 — заголовок крупно (30 pt), остальные — мелко (20 pt).
- ИИ-дополнение и подпись «КУБ-СКРИПТ» — только на последнем слайде.
- Выбранный шрифт присваивается каждому run (заголовок, тело, дополнение).

## Почему всё в `to_thread`

ReportLab/pptx/docx, Pillow и `_ask_ai` — синхронные и блокирующие.
`asyncio.to_thread` выносит их в пул потоков: бот продолжает отвечать
другим ученикам, пока генерируется файл.
