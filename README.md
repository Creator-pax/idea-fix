# MAX Школьный помощник

<!-- Проект в двух словах: бот для мессенджера MAX, который помогает
     школьникам с учёбой. Ниже — краткое описание для читателя, дальше
     по файлу будет много деталей. -->

Бот для мессенджера **MAX** (`https://max.ru`), который помогает школьникам
с учёбой: отвечает на вопросы по урокам, составляет расписание, генерирует
тесты, помогает с домашкой, ведёт заметки и настраивает интерфейс под себя.

Для администраторов/учителей есть панель модератора (`moderator_app.py`),
через которую можно подтверждать заявки на регистрацию, блокировать
пользователей и менять лимиты ИИ.

Ученик может в любой момент **подать заявку на вступление в другую школу
и класс** — учитель этой школы увидит заявку и сам решит, принимать или
отклонять. Также можно **выйти из школы** через настройки.

## Настройка ИИ (LM Studio)

Бот работает с **LM Studio** — бесплатным локальным сервером для LLM.

1. Скачай и установи LM Studio: `https://lmstudio.ai/`
2. Внутри загрузи модель (например, `qwen2.5-coder-0.5b-instruct`)
3. В разделе **Developer** включи локальный сервер (порт по умолчанию `1234`)
4. Убедись, что адрес совпадает с тем, что ожидает бот:
   `http://localhost:1234/v1/chat/completions`

Если LM Studio не запущен — бот не упадёт, а вежливо сообщит пользователю,
что сервер ИИ недоступен (см. `_ask_ai` в `handlers/ai.py`).

Лимиты запросов настраиваются в `config.py`:

```python
AI_DAILY_LIMIT_STUDENT = 50    # запросов в день для ученика
AI_DAILY_LIMIT_TEACHER = 100   # запросов в день для учителя
```

## База данных

SQLite-файл `bot_data.db` создаётся автоматически при первом запуске.

| Таблица           | Назначение                                                        |
|-------------------|--------------------------------------------------------------------|
| `users`           | Пользователи: роль, телефон, школа, класс, лимиты, chat_id и т.д. |
| `notes`           | Заметки пользователей                                             |
| `ai_log`          | История запросов к ИИ (для логирования учителям)                  |
| `ai_errors`       | Лог ошибок ИИ (виден в панели модератора)                         |
| `join_requests`   | Заявки учеников на вступление в школу/класс (учитель подтверждает)|

### Важная идея: «одна операция = одно соединение»

БД открывает **новое соединение на каждую операцию** (функция `_get_conn`
в `database.py` оправдывает название: каждая функция сама открывает
и закрывает соединение через контекстный менеджер `_connect`).

Почему так сделано:

- SQLite-соединения нельзя разделять между потоками;
- когда каждое чтение идёт с диска «с нуля», **два процесса** (бот
  и панель модератора) всегда видят свежие данные друг друга —
  какие бы изменения ни внёс второй процесс;
- включён режим `journal_mode=WAL`, поэтому читатели не блокируют
  писателя и наоборот;
- `busy_timeout=15000` — если файл временно занят другим процессом,
  подождём до 15 секунд.

### Автоматическая миграция

Схема создаётся через `CREATE TABLE IF NOT EXISTS` — она идемпотентна.
Но новые колонки в уже существующей таблице `CREATE TABLE IF NOT EXISTS`
**не добавляет**. Поэтому при каждом старте вызывается
`_migrate_users_columns()`, которая через `PRAGMA table_info(users)` находит
отсутствующие колонки и дописывает их через `ALTER TABLE`.

Так, например, к старым базам добавляются колонки `blocked`, `show_emoji`,
`compact_mode`, `show_stats`. Поэтому **старые базы не нужно пересоздавать** —
бот сам всё достроит при запуске.

## Регистрация и модерация

### Как проходит регистрация

1. Пользователь нажимает `/start` и выбирает роль (ученик/учитель).
2. Шаг за шагом вводит телефон → пароль → имя → (ученик: класс) → школу.
3. Все шаги — это FSM-состояния (см. `handlers/states.py`).
4. После финального шага заявка попадает в статус `pending`.
5. Модератор подтверждает её в разделе «🛡 Модерация» → «📋 Заявки».
6. Пользователь получает личное уведомление (`_notify_approved`).

Если `REQUIRE_MODERATION = False` в `config.py` — заявка подтверждается
автоматически без участия модератора.

### Модерация в чате

В разделе «🛡 Модерация» главного меню модератору доступны инструменты:

- **📋 Заявки** — поочерёдный просмотр и подтверждение/отклонение заявок;
- **👥 Все пользователи** — список с ролями и статусами (🚫 — заблокирован);
- **🔎 Пользователь по ID** — полная карточка пользователя с быстрыми действиями:
  блокировка/разблокировка, смена роли (ученик/учитель/модератор), смена лимита ИИ,
  удаление из базы (с подтверждением);
- **🚫 Блокировка** — заблокировать/разблокировать по user_id;
- **🔧 Лимиты ИИ** — изменить дневной лимит запросов ученику;
- **📢 Рассылка** — отправить сообщение всем подтверждённым пользователям;
- **⚠️ Ошибки ИИ** — просмотреть и очистить лог ошибок;
- **🏫 На вступление** — заявки учеников на вступление в школу.

Заблокированные пользователи не могут пользоваться ботом: им показывается
уведомление о блокировке вместо меню.

## Школа и класс (заявки на вступление)

Этот механизм позволяет ученику:

- **подать заявку** на вступление в конкретную школу и класс;
- **выйти из школы** (отвязаться от школы и класса без удаления аккаунта);
- **следить за статусом** своей последней заявки (ожидает / принята / отклонена).

А учитель/модератор может заявки **принимать или отклонять**.

### Таблица join_requests

```
id            INTEGER PRIMARY KEY AUTOINCREMENT  -- номер заявки
user_id       INTEGER  -- кто подал заявку
target_school TEXT     -- школа, в которую хочет вступить
target_class  TEXT     -- класс, в который хочет вступить
status        TEXT     -- pending / approved / rejected
teacher_id    INTEGER  -- кто обработал заявку (user_id)
time          INTEGER  -- когда подана заявка (unix)
```

### Как это работает в боте

**Сторона ученика** (handlers/settings.py):

1. Настройки → «🏫 Школа и класс».
   Бот показывает текущую школу/класс и статус последней заявки.
2. Кнопка «📝 Подать заявку» → FSM `wait_join_school` → вводим школу
   → FSM `wait_join_class` → вводим класс.
3. `db.create_join_request(user_id, school, class)` создаёт заявку
   со статусом `pending`.
4. Бот уведомляет учителей этой школы (`db.get_teachers_by_school`).

**Кнопка «Выйти из школы»:**

1. Показываем подтверждение (кнопки «✅ Да, выйти» / «❌ Остаться»).
2. При подтверждении вызывается `db.leave_school(user_id)` — поля
   `school` и `class_name` становятся пустыми.
3. Статистика и заметки не трогаются.

**Сторона учителя:**

1. Учитель открывает Настройки → «🏫 Школа и класс» → «📋 Заявки
   на вступление» (или «🛡 Модерация» → «🏫 На вступление» для модератора).
2. Видит первую заявку: имя, школа, класс, текущие данные ученика.
3. Жмёт «✅ Принять» / «❌ Отклонить» / «⏭ Пропустить».
4. `db.approve_join_request` обновляет школу/класс ученика на указанные
   в заявке и ставит статус `approved`.
5. Ученику приходит личное уведомление о решении учителя.

## Известные подводные камни

### Текст в кнопках «плывёт» / обрезается

У MAX жёсткие лимиты на видимый текст кнопки **в зависимости от количества
кнопок в одном ряду**:

| Кнопок в ряду | Макс. символов в тексте кнопки |
|---------------|--------------------------------|
| 1             | 20                             |
| 2             | 10                             |
| 3             | 5                              |
| 4+            | 3                              |

`KeyboardBuilder` из `maxo` раскладывает кнопки по **7 в ряд** по умолчанию,
поэтому если просто вызвать `add_callback(...)` подряд много раз — длинный
русский текст и составные эмодзи будут резаться посреди символа.

**Решение:** для клавиатур-«списков» (меню, заметки, настройки) всегда
вызывать `.adjust(1)` — по одной кнопке в ряд:

```python
kb = KeyboardBuilder()
kb.add_callback(text="❓ Вопрос по уроку", payload="ai_question")
kb.add_callback(text="📋 Мои заметки", payload="menu_notes")
return kb.adjust(1)   # по одной кнопке в ряд -> текст не режется
```

Если нужны кнопки по 2+ в ряд — держи текст коротким (до 10/5/3 символов).

### Регистрация и FSM

Незавершённая регистрация хранит состояние в FSM (`handlers/states.py`).
Кнопка «Назад в меню» **не сбрасывает** процесс регистрации, чтобы случайно
не потерять введённые телефон/пароль — это сделано сознательно
(`_is_registration_state` в `handlers/menu.py`).

### Изменение названия школы

Заявки на вступление фильтруются по **точному совпадению** названия школы
(строка сравнения). Если ученик напишет «Школа №15», а у учителя в профиле
«школа 15» — учитель не увидит заявку. Попросите учителей и учеников
использовать одинаковое название школы (например, «Школа №15»).

## Как расширять бота (шпаргалка)

1. **Найди подходящий роутер** в `handlers/`. Если функция относится
   к настройкам — в `settings.py`, к модерации — в `moderation.py` и т.д.
2. **Добавь кнопку** в соответствующую клавиатуру `KeyboardBuilder`,
   придумай ей уникальный payload (короткая строка, например `my_new_feature`).
3. **Зарегистрируй payload** в `CallbackPayload(...)` декоратора роутера.
   Если в payload будут числа — добавь в `prefixes=("my_new_feature_",)`.
4. **Напиши ветку** в обработчике (`if payload == "my_new_feature": ...`).
5. Если нужно ждать текст от пользователя — добавь состояние в
   `handlers/states.py` (нужный `StatesGroup`), переведи пользователя через
   `await fsm_context.set_state(...)` и напиши `StateFilter(...)`-обработчик.
6. Если нужны новые данные — добавь таблицу/функции в `database.py`.
7. **Проверь**: `python -m py_compile` на всех изменённых файлах
   и `python -c "import handlers"`.
8. Имена кнопок должны быть короче 20 символов, при нескольких кнопках
   в ряду — ещё короче (см. раздел «подводные камни»).
